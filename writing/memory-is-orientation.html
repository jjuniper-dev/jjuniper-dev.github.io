Memory is orientation, not a project database.

October 2026

When an AI assistant remembers things about you, it is tempting to let it remember everything: ticket numbers, build results, what was blocked last Tuesday. I think that is a mistake, and the reason is about authority, not storage.

Two kinds of fact

Some facts stay true for months: what you do, what you care about, how you like answers shaped, the principles you work by. Other facts expire quickly: whether a change was merged, whether a test passes, who owns a follow-up. The first kind is worth remembering. The second kind is worth looking up.

If an assistant answers "what is the current status?" from memory, it is giving you a confident account of a past moment. The right behaviour is to say where the answer lives and go and read it there.

A stack, not a pile

The model I use has five layers. Memory holds stable principles and preferences. Context holds relevant history and the current working state. Control holds decisions and approvals. Execution holds the code and the workflows. Evidence holds the validated results. Each layer down is more authoritative about what is true now. The assistant starts at the top to get oriented and checks the bottom before it asserts anything current.

Why it matters beyond convenience

A stale fact stated with confidence is worse than a gap, because nobody thinks to check it. Keeping volatile detail out of long-term memory is a small piece of discipline that keeps an assistant honest about the difference between what it recalls and what it has verified.

There is a second benefit. A memory that holds only durable things stays short enough to read, and so stays useful.

This is a personal note about how I use AI assistants. It reflects my own working habits, not the position of any organization I work with.
